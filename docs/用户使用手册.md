# 工具使用手册

面向使用者的操作说明。平台把 OWASP Dependency-Check 封装成 Web 服务：上传工程压缩包，后台扫描，页面查看漏洞与许可证结果，并下载报告。

---

## 1. 环境与启动

| 项 | 要求 |
|---|---|
| 浏览器 | Chrome / Edge / Firefox |
| 后端 | JDK 21，`java -jar target/depcheck-1.0.0.jar`（默认 8080） |
| 前端 | Node 20/22，`cd frontend && npm install && npm run dev`（默认 5173） |
| 漏洞库 | `depcheck.scan.data-dir` 指向已建好的 NVD 库（见《本地环境搭建手册》） |

打开 **http://localhost:5173**。首次启动会自动建表；若提示端口占用或数据库被锁，说明已有实例在运行。

---

## 2. 登录

- 使用管理员分配的**固定账号**，无需注册。
- 连续输错 5 次会锁定 1 分钟。
- 同一账号在任何浏览器登录，都能看到自己提交的任务与报告。

---

## 3. 上传工程

1. 进入「上传与扫描」；
2. 把 `.zip` 拖进虚线框（或点击选择）；
3. 点「上传并解压」。

限制与校验：

| 项 | 规则 |
|---|---|
| 格式 | 只接受 `.zip`（改后缀也会被文件头校验拦下） |
| 大小 | ≤ 512 MB |
| 解压后 | ≤ 2 GB、≤ 5 万文件 |
| 安全 | 拒绝路径穿越（Zip Slip）的压缩包 |

> 建议把整个工程目录（含 `pom.xml` 与 `target/`）打成 zip，这样引擎能分析到实际 jar。

---

## 4. 提交扫描与查看进度

上传成功后点「开始扫描」，自动跳到任务详情。

| 阶段 | 含义 |
|---|---|
| 准备中 | 校验工程路径 |
| 采集依赖 | 扫描 jar / 目录 |
| 漏洞分析 | 比对 NVD（最慢，通常占 80% 时间） |
| 生成报告 | 输出 HTML / JSON |
| 写入数据库 | 解析报告并入库 |

参考耗时：小型工程 4–5 秒；含 283 个文件的 petclinic 约 15–17 秒。页面每 2 秒自动刷新，结束后停止。

---

## 5. 读懂结果

「任务详情」页在扫描成功后展示：

| 区域 | 内容 |
|---|---|
| 四张统计卡 | 依赖总数、漏洞总数、严重+高危、许可证高风险 |
| 漏洞 Tab | CVE、CVSS、等级、所属依赖、CWE（按 CVSS 从高到低，无评分排最后） |
| 依赖 Tab | 依赖名、版本、许可证、风险等级、该依赖命中的漏洞数 |

等级参考：CRITICAL ≥ 9.0、HIGH 7.0–8.9、MEDIUM 4.0–6.9、LOW < 4.0。
许可证四档：HIGH（GPL/AGPL/SSPL）、MEDIUM（LGPL/MPL/EPL）、LOW（Apache/MIT/BSD/ISC）、UNKNOWN。

---

## 6. 报告下载

- 详情页右上角「下载报告」，或进入「报告下载」页按列表下载；
- 报告为 HTML（引擎原生输出），文件名为 `dependency-check-<任务ID>.html`；
- 报告按保留策略清理后，列表显示「已清理」，重新扫描即可再生成。

---

## 7. 取消与失败处理

| 场景 | 行为 |
|---|---|
| 排队中取消 | 立即变为「已取消」，不留文件 |
| 执行中取消 | 在当前阶段结束时生效（最长约 12 秒），报告目录删除、不写入数据库 |
| 扫描失败 | 任务标记失败并给出错误码；失败的扫描不会留下半量数据 |

错误码对照：

| 码 | 含义 | 处理 |
|---|---|---|
| 1001 | 参数不合法 | 检查入参 |
| 1002 | 未登录 / 账号或密码错误 | 重新登录或核对密码 |
| 1003 | 资源不存在或无权访问 | 确认任务属于当前账号 |
| 1004 | 系统繁忙 / 登录过于频繁 | 稍后重试 |
| 2001 | 文件超限 | 压缩包 ≤ 512 MB |
| 2002 | 非法 ZIP | 重新打包（含路径穿越的包会被拒） |
| 2003 | 解压后过大 | 拆分工程或排除无关目录 |
| 3001 | 扫描失败 | 看详情页错误信息，多为漏洞库路径不对 |
| 3002 | 扫描超时 | 检查工程规模，必要时调大超时 |
| 3003 | 服务重启中断 | 重新提交任务 |

---

## 8. 数据保留

| 对象 | 保留时间 | 说明 |
|---|---|---|
| 失败任务报告 | 24 小时 | 便于排障 |
| 成功任务报告 | 7 天 | 过期后可重新扫描生成 |
| 项目与解压目录 | 30 天 | 到期自动清理（含任务与明细） |

均可在 `application.yaml` 的 `depcheck.retention.*` 调整。

---

## 9. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面打不开 | 前端没起 | `cd frontend && npm run dev` |
| 登录报「无法连接后端」 | 后端没起或端口不对 | 确认 8080 在监听；换端口时前端用 `VITE_API_TARGET` |
| 依赖数为 0 | 包里没有 jar（只有源码） | 把 `target/` 或依赖 jar 一起打包 |
| 扫描很慢（>1 分钟） | 引擎在做全量分析 | 正常；大工程更久，可看阶段进度 |
| 报告打不开 | 已过保留期 | 重新扫描 |
| 启动报「file is locked」 | 已有实例占用业务库 | 停掉旧进程再启动 |

---

## 10. 限制

- 仅内网使用，禁止上传含敏感信息的代码；
- 主要面向 Java/Maven 工程，NPM 仅基础分析；
- 服务端并行 2 个任务、队列受理 8 个，超出返回 1004。
